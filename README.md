# 驻点就业服务站：面谈登记到雇主接人

在季节工面谈语料（`data/corpus.json`，记录类型见 `data/context.json`）之上，
实现从面谈登记、岗位撮合、签约把关到接站交接的完整工作台。仅使用 Python 3.11
标准库。

## 业务规则如何落地

### 1. 原话与结构化判定并存
每条面谈长句按逗号/句号拆成独立意愿，原话整段保留在 `original_text`，
单句原话保留在 `Statement.quote`，所有结构化字段都带 `source_id` 回链。
方言转写和普通话补述都不会被覆盖，结构化信息只用于核对与撮合。

### 2. 意愿归属与待核实项（`parser.py` + `models.Ambiguity`）
- “夜里能不能上你要问她”登记为**夜班意愿转问他人**，不计本人同意；
- “她同车的话我能考虑”中的“她”有两种有据解释（C11/C13），登记为
  `Ambiguity` 留给经办人核实，本人已明确的接站等条件照常进入撮合；
  后续本人确认 RE1 明确同行范围为 C13 后，合同条件才指向 C13；
- “没说不去”“没一起定过”只能得到 `UNSTATED`，不产生任何同意；
- “我第一晚得有人接”是**提出条件**（`PICKUP_CONDITION`），
  不等于已接受某个接站人；
- “最好同车”是软偏好（`PREFERENCE`，可接受别的班次），
  “若……同车我才接受/才生效”才是硬性条件（`HARD_COMPANION`/合同生效条件）；
- “后续可申请转白班”不改变 J3 的首日晚班（`ShiftType.FIRST_NIGHT`）；
- “先别替我签”登记禁止代签；缺少本人明确同意的合同判为 `BLOCKED`。

### 3. 签约把关（`engine._evaluate_contracts`）
雇主承诺与本人同意齐备后才判 `READY`（可签）；附生效条件但条件未落实的判
`HELD`（暂留，继续跟进，不取消）；缺本人同意的判 `BLOCKED`。
- R1（C11→J1）独立签认、未约定同车为条件 → **可签**；仅交通待落实时合同保留；
- R2（C12→J2）须 C13 同趟两席且东站有人接 → 条件未满足，**暂留**；
- R3（C13→J3）须同趟并在报到期限内抵达东站 → 条件未满足，**暂留**。

### 4. 运输变更与席位分配（`engine._apply_leg_changes` / `_allocate_seats`）
- C91 取消 → 班次 `CANCELLED`、接站单 `WITHDRAWN`，状态留存可查；
- C92 故障换车 → 原班次 `REPLACED`、原接站单 `SUPERSEDED`，
  新班次 V2-NEW 18:58 到东站（19:00 截止内），按变更显式容量只剩一席；
  已出票的 C11 硬承诺席位优先保留；
- 西站备选 18:20 到站加 60 分钟转运 = 19:20，超过截止 → `INFEASIBLE`；
- 硬同行 C12/C13 在只剩一席时**不拆开**凑录用数，转再确认；
  软偏好不产生硬同行约束，也不消耗受保护席位。

### 5. 再确认任务（`Reconfirmation`）
每个任务写清**哪一段接运、由谁确认、挂接哪份合同**：
- T1：V2-NEW 换车后的上车点/班次，由 C11 本人接受后继续；
- T2：V1 取消后的同趟两席与同行范围，由 C12、C13 重新确认；
- T3：西站备选由 C12 按其本人确认重新确认（且该段已超报到期限）。

### 6. 接站单与交接包（`PickupSheet` / `HandoverPacket`）
- 旧单的领取、撤回、被接替状态全程可查（含 `history` 事件）；
- 换发新单的上车点为 `None`，**不得沿用旧集合点“桥口”**，核实前显示待核实；
- 交接包只含白名单四字段：联络码、发车时间、上车点、接站人。
  岗位编号、宿舍、家庭原话、人名一律不出现；撤回/已接替的旧单拒绝交接。

## 经办人查询（CLI）

```bash
python3 -m employment_station report      # 完整工作台（六节）
python3 -m employment_station reconfirm   # 接运再确认清单（段/确认人/挂接合同）
python3 -m employment_station sheets      # 接站单领取、撤回、换发状态
python3 -m employment_station handover M2-单-换发   # 生成接站方交接包
```

## 代码结构

```
employment_station/
  models.py   领域模型：意愿强度、待核实项、岗位、接运、合同、接站单、交接包
  parser.py   语料解析：原话拆分、姓名↔代号解析、条件与来源回链
  engine.py   变更应用、席位保护与分配、签约判定、再确认、交接包白名单
  cli.py      经办人命令行
tests/        29 个用例，覆盖解释规则、运输、合同、交接与兜底合成场景
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

原始资料校验仍由 `tests/test_materials.py` 负责；业务规则测试在新增的四个
模块中。所有人物与业务往来均为合成演练资料。
